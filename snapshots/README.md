# Snapshots

This directory contains primary measurement artifacts.

Snapshots represent confirmed capture events recorded under normal operating conditions and preserved as archive evidence.

Once committed, snapshot artifacts are not modified in place.

---

## Definition

A snapshot is a:

- date-stamped measurement event
- primary artifact generated by a device, lab, scan, or capture process
- record archived without retrospective alteration

Examples include:

- DEXA outputs
- BodPod outputs
- bloodwork captures
- scan images
- exported PDFs tied to a specific capture window

---

## Structure

Snapshots may be stored either:

- as date-named files at the root of `/snapshots`, or
- inside date- or epoch-labeled subdirectories when a capture window contains multiple related artifacts

Subdirectories may include:

- `README.md` for capture context
- image artifacts
- PDF artifacts
- grouped files from the same measurement window

The archive may contain legacy and current foldering patterns.  
Artifacts remain valid as long as dating, naming, and traceability are preserved.

---

## Naming Convention

Artifacts should follow a date-first convention:

`YYYY-MM-measurement-type.ext`

Examples:

- `2026-02-dexa-body-comp.jpg`
- `2026-02-bodpod-results.pdf`
- `2025-11-bloodwork-panel.pdf`

Use:

- lowercase
- hyphen-separated descriptors
- date first

Descriptive names should remain concise and readable.

---

## Integrity Policy

- artifacts are never overwritten
- corrections require new commits
- dating must remain visible
- traceability must remain intact
- deviations from capture protocol must be documented when relevant

Snapshots are evidence first, interpretation second.
