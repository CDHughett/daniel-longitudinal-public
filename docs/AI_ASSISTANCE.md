# AI Assistance Disclosure

## Purpose

This document describes how AI/large-language-model assistance may participate in maintenance of the Daniel Longitudinal Study.

AI assistance is part of the working process.

It is not a source-evidence class and does not receive authority over preserved measurements.

---

## Permitted Assistance Roles

AI systems may assist with:

- drafting and editing repository documentation
- structuring information already present in governed sources
- converting source-backed observations into machine-readable rows
- proposing schemas and controlled vocabularies
- identifying cross-file inconsistencies
- calculating reproducible summaries from specified source values
- supporting repository audits
- reviewing links, metadata, and governance alignment
- proposing prospective predictions for the governed model-error layer
- comparing a registered prediction with later admissible evidence after the scoring boundary closes
- generating code for validation or reproducible analysis

AI-assisted work must remain reviewable through the same source and governance rules as manually produced repository work.

---

## Prohibited Authority

AI output must not be treated as sufficient authority to:

- invent a missing observation
- replace an unresolved value with a plausible estimate
- override a verified source artifact
- silently alter a canonical value
- rewrite a registered prediction after outcome access
- convert candidate evidence into a closed result without the registered criteria
- create a phase transition from narrative confidence
- infer clinical meaning beyond the preserved evidence
- conceal unfavorable evidence
- manufacture source provenance
- fabricate a private-source checksum

When AI output conflicts with stronger source evidence, the source hierarchy governs.

---

## Source Hierarchy Remains Primary

The governing evidence hierarchy remains defined by the repository's methodology and governance documents.

AI-generated prose, classification, or code does not outrank:

1. verified primary source artifacts
2. direct provider/device exports
3. contemporaneous structured transcription
4. contemporaneous collection notes
5. closed retrospective reports
6. later evidence-grounded synthesis

AI assistance is a method of working with those layers, not an additional evidentiary layer.

---

## AI-Assisted Structuring

Some public structured datasets may be created or expanded with AI assistance from governed private/public sources.

When that occurs:

- the public row should retain a `source_ref`
- private-source versions should remain identifiable where applicable
- missingness must remain visible
- unsupported precision must not be introduced
- source wording may be normalized only within the declared schema rules
- material source conflicts require explicit reconciliation

The accepted repository state represents the maintained archive decision, not autonomous model authority.

---

## AI-Generated Predictions

The model-error layer explicitly records model versions for predictions where applicable.

AI-generated predictions may enter the primary model-error layer only when they satisfy the archive's forward-prediction criteria, including:

- registration before relevant outcome access
- a defined observation/scoring window
- falsifiability
- sufficient specificity
- preserved original prediction wording
- later closure under the applicable evidence boundary

Prediction accuracy is not evidence that the AI system has general clinical or scientific authority.

Prediction failure remains preserved.

---

## AI and Retrospective Analysis

AI may assist after an observation window closes by:

- recomputing arithmetic
- locating contradictory evidence
- comparing sources
- drafting bounded retrospective interpretation
- identifying possible model error

Retrospective AI assistance must not be represented as though it were a prospective prediction made before the outcome.

---

## AI and Validation Code

AI may help write validator or analysis code.

Code remains subject to:

- source review
- repository history
- explicit tests/checks
- human semantic review
- correction if implementation defects are identified

A passing validator confirms only the checks implemented by that validator.

It does not independently establish biological validity.

---

## Disclosure Boundary

This document discloses the role class of AI assistance.

It does not imply that every line, commit, classification, or calculation was generated by AI.

Likewise, the absence of a per-line AI label does not imply that no AI assistance occurred.

Where the identity/version of a model is methodologically relevant — especially in the prediction layer — it should be preserved in the corresponding structured record.

---

## Privacy Boundary

Private source material may be reviewed during AI-assisted archive maintenance only within the user's authorized working environment.

The public repository should publish only the governed public derivative/provenance information required for auditability.

Private-source hashes may be registered without publishing the private source file itself.

## Archive Principle

AI may increase the speed and depth of archive maintenance.

It must not increase the strength of a claim beyond the evidence supporting that claim.
